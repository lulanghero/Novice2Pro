## 一、项目背景

在疫情之后，远程协作成为软件开发的常态，GitHub 已发展为全球最重要的开源协作平台之一。
然而，大量新开发者在进入开源社区时仍面临系统性障碍：

* 项目选择困难：无法判断项目是否新手友好
* 社区健康度不可感知：Issue / PR 活跃是否意味着良性协作？
* 贡献反馈滞后：个人贡献价值难以及时量化
* 学习路径碎片化：缺乏从“新手”到“稳定贡献者”的成长指导

**Novice2Pror** 旨在利用 **OpenSODA 提供的真实 GitHub 行为日志与 OpenDigger（OpenRank）指标体系**，构建一个：

> **“可解释、可量化、可持续激励”的开源学习与成长智能体系统**

---

## 二、项目核心思想

> **用真实开源行为数据构建知识图谱，用 RAG + AI Agent 把“开源怎么参与”这件事解释清楚。**

## 四、RAG 在项目中的作用

### 4.1 RAG 不是“查资料”，而是“结构化经验”

本项目中的 RAG（Retrieval-Augmented Generation）并非简单的文本检索，而是用于：

* 承载 **GitHub 行为日志、项目协作模式、OpenRank 指标**
* 将原始事件 → 实体 → 关系 → 行为模式
* 为 Agent 提供**可追溯、可解释的参考资料**

### 4.2 RAG 的核心职责

| 能力   | 说明                 |
| ---- | ------------------ |
| 实体抽取 | 开发者、项目、Issue、PR、指标 |
| 关系建模 | 行为序列、协作关系、生命周期     |
| 描述摘要 | 将日志转为“人能读懂的事实”     |
| 检索支持 | 为 Agent 提供【参考资料】   |

### 4.3 GraphRAG 的实现方式

* **离线构建知识**
* **在线只做检索**
* 不在推理阶段重新分析原始大数据

这也是为什么仓库中 **不直接包含 OpenSODA 全量数据集**。

---

## 五、Agent 在项目中的作用

Agent 并不直接“懂开源”，而是：

> **在 RAG 提供的事实基础上，完成推理、规划与解释**

### 当前 Agent 的能力定位

* 调用 RAG 获取结构化【参考资料】
* 基于 Prompt 模板完成：
  * 技战术分析
  * 行为解释
  * 关系重组（如时序图、流程图）
* 保证：
  * **RAG 不被污染**
  * **对话上下文与知识检索解耦**

Agent 本身 **不绑定特定数据集**，可以复用在不同知识库场景。

## 六、one-api 在项目中的角色

### 为什么需要 one-api？

* 本项目 **不绑定任何具体模型**
* 所有 LLM / Embedding 能力统一通过 one-api 提供
* 对上层完全暴露 **OpenAI-compatible API**

### one-api 的职责

| 功能     | 说明                 |
| ------ | ------------------ |
| 模型路由   | 本地 / 云端模型统一管理      |
| Key 管理 | 用户自行配置             |
| API 统一 | RAG / Agent / 前端解耦 |

```text
RAG / Agent / Frontend
        ↓
OpenAI-compatible API
        ↓
      one-api
        ↓
   实际模型（可替换）
```

## 七、数据来源与数据策略

### 7.1 数据来源

* GitHub 2020 年 1 月全域日志
* GitHub Top300 仓库历史日志（2020–2023）
* OpenDigger 指标数据（含 OpenRank）

### 7.2 为什么仓库里没有全量数据？

* 数据体量巨大（GB 级）
* 不适合直接放入 GitHub
* 本项目采用：

> **“外部数据 + 本地 RAG 构建 + 轻量仓库”** 的工程实践方式

### 7.3 仓库中实际包含的是什么？

* RAG 构建逻辑
* Prompt 模板
* 缓存结构
* 示例输入
* Agent 与服务代码

## 九、总结

**Novice2Pro** 并不是一个“堆模型”的项目，而是一次：

> **将真实开源行为 → 数据方法论 → RAG 知识结构 → AI Agent 推理**
>
> **完整串联起来的工程化尝试**

它展示的不是“模型多强”，而是：

* 如何让新手**看懂开源**
* 如何让贡献**被解释**
* 如何让激励**有依据**
